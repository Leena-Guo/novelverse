# 书声 · 小说阅读与听书平台

一个把网络上各类免费小说**抓取整合**到本地的阅读站：支持**推荐 / 关键字搜索 / 分类浏览 / 在线阅读 / 听书（多音色）/ 书架收藏 / 阅读记录**。

> 零依赖，只用 Node.js 内置能力（`node:http` + `node:sqlite` + 全局 `fetch`），下载即跑。

## 🚀 快速开始

```bash
cd novelverse
npm start          # 启动服务（默认 http://localhost:8787）
```

首次启动会用**离线兜底书库**（3 本原创示例）保证站点立即可用。联网后执行抓取即可把书库扩充到数千～数万本：

```bash
npm run sync          # 浅抓：各分类人气榜（默认每分类 2 页，最快）
npm run sync 3        # 浅抓：每分类抓 3 页
npm run sync:full     # 浅抓：各分类人气榜（每分类 2 页）
npm run sync:deep     # 【全量】遍历 全部分类 × 全部榜单 × 每榜 10 页（约 8000+ 本）
npm run sync:deep 5   # 【全量】每榜只抓 5 页
npm run sync:ultra    # 【深度全量】再叠加 字数段 × 连载状态，广度优先深挖长尾（数万本，耗时较久）
```

> **书源实测容量**：`m.biqugen.com` 的列表页 URL 形如
> `/list/<榜单>_<分类>_<字数段>_<状态>_<页码>.html`，每个「榜单 × 分类 × 字数段 × 状态」组合约暴露 10 页（每页 30 本）。
> 遍历 **12 种榜单 × 7 个分类 × 6 档字数 × 3 种状态** 后，理论上可覆盖源站 **30 万+** 本书目中的很大一部分。
> - `sync:deep`：只遍历「分类 × 榜单」（≈600 次请求）→ 约 **8000+** 本。
> - `sync:ultra`：额外遍历「字数段 × 状态」，**广度优先**（每个组合抓第 1 页，≈1500 次请求）→ 快速逼近数万本；该任务较久，网页端可**随时停止**。

也可以直接打开站点底部的 **「抓取与书库状态」** 页面：点「🚀 全量抓取（抓满书源）」或「📚 深度抓取（挖长尾）」按钮即可在网页里**后台抓取**，页面实时显示进度、可一键停止。

#### 多书源（不止笔趣阁）

搜索**并发聚合所有已注册书源**，结果里标注来源（如「笔趣阁」「笔趣书阁」），可分别「导入」到本地书库。
某本书若只在某一源存在，也能被搜到——例如《我的师兄实在太稳健了》只有笔趣书阁收录。

| 书源 | 站点 | 说明 |
| --- | --- | --- |
| 笔趣阁 | `m.biqugen.com` | 移动站，书目量大；正文 `qsbs.bb` 混淆，需解码 |
| 笔趣书阁 | `www.bqg10.cc` | 补充索引；正文在 `#booktxt`，多页章节自动合并 |

> 适配器只需实现 `listBooks / search / bookDetail / chapterListPage / chapterContent` 五个方法。
> 同模板镜像站可用工厂函数一行注册：`makeBiqugeSite({ id, name, base })`（见 `src/crawler/index.mjs`）。
> 已实测排除的候选源（模板不一致 / 目录由 JS 懒加载 / SSL 或超时不稳定）：`biquge365.net`、`88biquge.com`、`blqukan.cc`、`xshuquge.net`、`xbiquwk.com`、`bqg221.com` 等。

> 环境变量：`PORT`（默认 8787）、`CRAWL_CONCURRENCY`（抓取并发，默认 12；调高可显著加快「离线下载」，调低以减轻源站压力）、`CRAWL_TIMEOUT`（毫秒）、`SOURCE`（默认书源）、`PREFETCH_CHAPTERS`（阅读时服务端后台预取章数，默认 3）。

### 自动抓取与每日更新

```bash
npm run update          # 手动执行一次“每日维护”（更新已有 + 扩充书库 + 清理违规）
npm run update expand   # 仅扩充书库
```

- **搜索自动补充**：在搜索页搜索时，若本地书库没有相关作品，会自动联网抓取网络书源并入库（每次最多 `AUTO_FETCH_LIMIT`，默认 15 本）。搜索页会提示“自动补充了 N 本”；重复搜索不会重复添加。
- **每日自动更新**：服务启动后内置调度器，默认**每天 01:00（服务器本地时间）**自动运行：① 遍历各分类 × 各榜单抓取，发现新的免费小说即入库；② 按“最久未检查优先”挑选已入库小说，检查是否有更新，有新章节则补全目录（新章节正文仍按需抓取）；③ 先清理库内违规作品。
- 可在「抓取与书库状态」页查看**下次执行时间**、**待检查书籍数**、以及**最近日志**，也可点「立即执行每日维护」手动触发。
- 若不想依赖常驻进程内的定时器，也可关闭内置调度（`AUTO_UPDATE=0`）改用系统 crontab：

  ```bash
  0 1 * * *  cd /path/to/novelverse && node --no-warnings scripts/update.mjs >> data/update.log 2>&1
  ```

相关环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `AUTO_FETCH_SEARCH` | `1` | 设为 `0` 关闭“搜索自动补充” |
| `AUTO_FETCH_LIMIT` | `15` | 每次搜索最多自动入库多少本 |
| `AUTO_UPDATE` | `1` | 设为 `0` 关闭每日自动更新 |
| `UPDATE_HOUR` / `UPDATE_MINUTE` | `1` / `0` | 每日执行时间（本地时间） |
| `UPDATE_SYNC_PAGES` | `3` | 每日扩充：每分类/榜单抓取页数 |
| `UPDATE_DEEP` | `1` | 每日扩充是否遍历“全部分类 × 全部榜单”（设为 `0` 仅抓各分类人气榜，更轻量） |
| `UPDATE_LIMIT` | `30` | 每日最多检查多少本已有小说 |
| `PREFETCH_CHAPTERS` | `3` | 阅读时服务端后台预取后续章节数（0 关闭；配合客户端预加载，翻章秒开） |
| `PORT` | `8787` | 服务端口 |
| `HOST` | `0.0.0.0`（一键脚本用 `127.0.0.1`） | 监听地址。设 `127.0.0.1` 则**仅本机可访问**（远端无法直连端口，只能经隧道，更安全） |
| `ACCESS_USER` / `ACCESS_PASSWORD` | `shusheng` / 空 | 设置口令后，**除本机 loopback 进程外**的所有来源（公网 / 局域网）都需口令或 `?k=` 令牌（详见「手机访问与部署」） |
| `SHARE` | `1` | 启动时是否自动建立外网隧道（设 `0` 关闭） |
| `SHARE_PROVIDER` | `auto` | `auto` / `quick` / `ngrok` / `tailscale` / `custom` |
| `SHARE_URL` | 空 | 固定网址（自建/命名隧道）；设置后只展示、不重复拉起隧道 |
| `SHARE_DOMAIN` | 空 | ngrok 固定域名（需配合 `NGROK_AUTHTOKEN`） |
| `NGROK_AUTHTOKEN` | 空 | ngrok 令牌（配合 `SHARE_DOMAIN` 得到固定网址） |
| `CRAWL_TIMEOUT` | `15000` | 抓取单次超时（毫秒） |
| `CRAWL_SEARCH_TIMEOUT` | `8000` | **搜索时**单源限时（毫秒，且不重试）；某源故障时最多等这么久，其余源结果照常返回 |
| `CRAWL_CONCURRENCY` | `12` | 同时向源站发起的抓取并发数。**「离线下载」速度主要由它决定**（实测 4→12 时 24 章从 6.6 秒降到 3.5 秒，约 1.9 倍）；源站若限流可回调到 4 |
| `TTS_PROVIDER` | `baidu` | 听书引擎：`baidu`（服务端在线合成，推荐）/ `azure`（需密钥）/ `browser`（仅浏览器 Web Speech） |
| `AZURE_TTS_KEY` / `AZURE_TTS_REGION` | 空 / `eastasia` | 使用 Azure 神经语音时填写（`TTS_PROVIDER=azure`） |

### 内容合规过滤（拦截违法涉黄作品）

- **入库拦截**：`src/moderation.mjs` 维护一份语义明确的成人/低俗词表，抓取（同步榜单、搜索自动补充、单本导入）时命中「书名 / 作者 / 简介」即**拒绝入库**；网络书源搜索结果也会先过滤再展示。
- **定期清理**：服务**启动时**、以及**每日维护**时都会扫描并删除库内命中违规的作品（连带章节、正文缓存、书架与阅读记录）。
- **手动兜底**：书籍详情页有「删除本书」按钮；「抓取与书库状态」页可「预览违规作品 / 清理违规作品」。
- 词表刻意保持克制（不收录「妻 / 婚 / 娇 / 老公 / 出轨 / 少妇」等正常言情常见词，避免误伤），因此可能仍有擦边作品漏网 —— 用上面的手动删除兜底即可。
- 可用 `BLOCK_TERMS=词1,词2` 追加自定义过滤词；`CONTENT_FILTER=0` 可整体关闭（不建议）。

  ```bash
  BLOCK_TERMS=奶文,肉香 npm start   # 在默认词表基础上追加
  ```

> 注意：该过滤基于书名/作者/简介等元数据，无法逐字审查正文内容。

## 📱 手机访问与部署

**默认行为**：`npm start` 后，服务会**自动建立外网隧道**，并打印手机可直接打开的网址；同时终端会输出一个**可扫码的二维码**。打开电脑浏览器访问 `/#/share` 还能看到「局域网 + 外网」两个二维码，用手机一扫即可进入。

```
  ▸ 本地访问:  http://localhost:8787
  ▸ 手机访问:  http://192.168.1.23:8787   （手机连同一 Wi-Fi 后，用浏览器打开）

  📱 外网访问地址：https://xxxx.trycloudflare.com
  🔳 二维码 / 局域网地址：用本机浏览器打开  http://localhost:8787/#/share
```

> 本项目的一键脚本（见下）出于安全只监听 `127.0.0.1`，**不会打印局域网地址**；手机统一走下面的固定外网网址，局域网直连需自行设 `HOST=0.0.0.0`。

手机打开后可「**添加到主屏幕**」，站内已内置 PWA，装到桌面后像 App 一样全屏使用。

### 本项目当前部署（已启用 Tailscale Funnel 固定网址 + 安全加固）

本机（WSL2）已配置好**固定外网网址**，并用一键脚本托管：

```bash
bash /root/.opencode/bin/novelverse/start-remote.sh
```

- **固定网址**：`https://<节点名>.<tailnet>.ts.net`（重启电脑后重跑脚本即可，网址不变）
- 脚本做的事：开启 Funnel → 停旧服务 → **以低权限用户 `shusheng`、只监听 `127.0.0.1`**、带访问口令重启
- 访问口令凭据：`.share_creds`（600 权限，含 `ACCESS_USER` / `ACCESS_PASSWORD`）
- 进程号写入 `.run_server.pid`，便于下次干净重启
- 手机建议：浏览器打开固定网址 → 输入一次口令（或扫码带 `?k=`）→ 菜单「**添加到主屏幕**」

**安全模型（重要）**：

| 访问来源 | 是否要口令 |
| --- | --- |
| 本机进程直连 `127.0.0.1`（loopback 且无 `X-Forwarded-*` 头） | **免密** |
| 公网（经 Tailscale Funnel） | **必须** 口令 / `?k=` 令牌 / Cookie |
| 局域网直连（默认已关闭） | 若开启 `HOST=0.0.0.0`，则**同样需要**口令 |

已落实的加固措施：

- **只监听 `127.0.0.1`**：远端无法直连端口，公网只能经隧道（隧道从本机 loopback 转发）；旧版「没有转发头就免密」的绕过已修复。
- **非 root 运行**：以专用系统用户 `shusheng` 运行（`setpriv` 降权），仅授予其穿越 `/root` 到项目目录的权限。
- **登录失败限流**：同一来源 10 分钟内失败 20 次即返回 `429`，冷却 10 分钟。
- **安全响应头**：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Permissions-Policy`、严格 `Content-Security-Policy`（`script-src 'self'`，无内联脚本），HTTPS 下附 `Strict-Transport-Security`。

**免密令牌（?k=）**：为免去手机每次输口令的麻烦，`/#/share` 页的二维码/链接会带一个令牌：

```
https://<节点名>.<tailnet>.ts.net/?k=<32位令牌>
```

- 用带令牌的链接访问，服务端会自动下发一个长期 Cookie，之后（含桌面图标）都免密；
- 令牌由 `ACCESS_USER + ACCESS_PASSWORD` 派生（`sha256`），改口令即失效重生成；
- **该链接等同密码**，请勿外发（已加 `Referrer-Policy` 减少 Referer 泄露）。

### 网址会不会变？（重点）
- **默认的 Cloudflare 临时隧道**：免费、零配置，但**每次重启网址都会变**（这是服务商机制，无法绕过）。
- **想让网址 / 二维码重启后不变**，配置下面任一种**固定网址**即可（都免费），配置一次永久生效：

| 方案 | 固定网址 | 需要 | 配置 |
| --- | --- | --- | --- |
| **ngrok 固定域名**（推荐） | `https://你的名字.ngrok-free.app` | 注册 ngrok 免费账号 | `NGROK_AUTHTOKEN=令牌 SHARE_DOMAIN=你的固定域名 npm start` |
| **自建 / 命名隧道** | 你自己的域名 | 一台隧道/域名 | 先在外部把隧道跑起来，再 `SHARE_URL=https://你的域名 npm start`（服务只做展示/二维码） |
| **Tailscale Funnel** | `https://节点名.xxx.ts.net` | 登录 Tailscale | `SHARE_PROVIDER=tailscale npm start` |

> 配置固定网址后，每次启动网址与二维码都不变，手机里收藏的书签/桌面图标也一直有效。

### 局域网直连（可选，默认关闭）
出于安全，一键脚本默认**只监听 `127.0.0.1`，局域网直连已关闭**。若确实需要手机在同一 Wi-Fi 下直连，启动时显式放开：

```bash
HOST=0.0.0.0 bash start-remote.sh      # 或： HOST=0.0.0.0 npm start
```

然后手机打开 `http://<局域网IP>:8787`。注意：此时局域网访问**同样需要口令/令牌**（不再免密）；防火墙若拦截请放行 `8787/tcp`。

### 访问口令（公网暴露时必备）
外网隧道默认是**公网可访问**的，务必设置口令：

```bash
ACCESS_USER=shusheng ACCESS_PASSWORD=你的密码 npm start
```

鉴权规则（`server.mjs`）：

| 访问方式 | 是否要口令 |
| --- | --- |
| 本机进程直连（loopback 且无 `X-Forwarded-*` 头） | **免密** |
| 公网（经隧道）/ 局域网直连 / 任何其它来源 | **需要** |

公网可用的三种鉴权方式（任一即可）：
1. **URL 令牌** `?k=<token>` —— 首次访问后自动写 `nv_auth` Cookie（`HttpOnly`、1 年），推荐给手机
2. **Cookie** `nv_auth=<token>`（由上面自动写入）
3. **HTTP Basic** 用户名/密码（兼容）

> 令牌 `token = sha256("novelverse:user:password").slice(0,32)`，见 `src/config.mjs`。
> Basic 认证在纯 HTTP 下是明文传输；经隧道（HTTPS）时才是加密的，故「口令 + 隧道」搭配使用最佳。

### 其他
- **只在本机用**：`SHARE=0 HOST=127.0.0.1 npm start`（不建隧道、不开放局域网），或单独执行 `npm run share` 手动开隧道。
- **关闭外网**：`SHARE=0 npm start`。
- **重启隧道**：访问页 `#/share` 点「重建隧道」，或 `POST /api/share/restart`。

### 开机自启
- **有 systemd 的宿主机**：见下方 unit 示例。
- **Docker**：给容器加 `--restart unless-stopped`（compose 里 `restart: unless-stopped`）。
- **无 systemd 的环境**：用 `pm2` / `supervisord`，或接入宿主机启动脚本。

```ini
# /etc/systemd/system/novelverse.service
[Unit]
Description=书声 小说阅读与听书平台
After=network.target

[Service]
WorkingDirectory=/path/to/novelverse
ExecStart=/usr/bin/node --no-warnings server.mjs
Restart=always
RestartSec=3
Environment=PORT=8787
# Environment=ACCESS_PASSWORD=你的密码
# Environment=NGROK_AUTHTOKEN=令牌
# Environment=SHARE_DOMAIN=你的固定域名
User=你的用户名

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now novelverse
```

> ⚠️ 默认开启外网隧道且未设口令时，任何拿到网址的人都能访问书库；长期公网使用请务必设置 `ACCESS_PASSWORD`。

## 🔌 抓取是怎么做的

书源适配器只需实现 4 个方法，即可接入任意镜像站：

```js
listBooks({ category, sort, page })   // 分类/排行榜列表
search(keyword)                       // 关键字搜索
bookDetail(sourceId)                  // 详情 + 首页章节
chapterListPage(sourceId, page)       // 章节列表分页
chapterContent(sourceId, ref)         // 章节正文（处理分页合并 + 编码还原）
```

当前内置两个书源：`biqugen`（笔趣阁移动站）与 `bqg10`（笔趣书阁）。关键处理：

- **列表/搜索/详情** 用少量正则精确解析（比引入解析库更轻、更快）。
- **章节正文** 源站用 `document.writeln(qsbs.bb('BASE64'))` 混淆 → 适配器提取全部 base64、解码、转成干净段落。
- **章节分页** 一章可能拆成 `xxx.html / xxx_1.html / xxx_2.html…`，适配器沿「下一章」链接判断并自动拼接。
- **目录分页** 每 100 章一页（`index_1.html` = 第 101–200 章），自动翻页汇总并去重排序。
- **目录去杂** 镜像站的「目录」里常混入作者公告 / 求票 / 推广 / 节日问候（“更新通知”“求月票”“推荐新书”“拜年”等），并非正文。适配层按「是否含章节标记（第 N 章 / 番外…）」判定，仅剔除无标记且命中公告关键词的条目，避免误伤标题里带“求月票”的正常章节。
- **垃圾过滤** 镜像站常掺杂 SEO 垃圾书名（“无弹窗 / 内容概括 / 笔趣阁…”），统一过滤。
- **有礼貌的爬虫** 全局并发闸门 + 请求间隔 + 超时重试 + UA 轮换。

### 抓取策略：目录全量、正文按需

- **书目**：列表页批量入库。浅抓（各分类人气榜）约十几次请求即可得数百本；`npm run sync:deep`（分类 × 榜单，≈600 次请求）约 **8000+** 本；`npm run sync:ultra`（再叠加字数段 × 状态，广度优先）可深挖到**数万本**。
- **目录**：打开某本书时才抓取它的完整章节表，并标记 `enriched`。
- **正文**：第一次阅读某章时抓取，落库 `chapter_contents` 缓存；之后直接读库。

这样既能「整合」大量书目，又不必预先下载海量正文。

## 🗄 数据模型（SQLite）

`books`（书目，含 `tags` 题材标签字段）、`chapters`（章节目录）、`chapter_contents`（正文缓存）、`users` / `bookshelf` / `history`（账号、书架与记录）、`sessions`（登录会话）、`crawl_logs`（抓取日志）、`meta`。

**账号体系**：`users` 表通过 `username`（唯一索引）、`password_hash`、`salt`、`is_account` 扩展为账号表，密码用 `scrypt` 加盐哈希；`sessions` 保存 30 天有效的登录令牌，通过 **HttpOnly Cookie**（`nv_session`）传递。登录后书架与记录归属账号（`owner = 账号 id`）；未登录仍以浏览器 `localStorage` 中的匿名 `clientId`（请求头 `X-Client-Id`）区分。**首次登录时会把当前浏览器的匿名书架/记录自动并入账号。**

**离线下载**：下载内容保存在**浏览器端**的 Cache Storage（`nv-downloads-v1`）中，Service Worker 在断网时回退读取，因此不占用账号空间、也无法跨设备同步。该功能需要**安全上下文**（HTTPS 或 localhost）：用外网隧道地址或本机地址访问即可；局域网 `http://IP` 下不可用（页面会提示）。断网听书请选择系统**本地音色**。

## 🔊 听书说明

- 默认使用**服务端语音（无需任何密钥）**：服务器把每段正文合成 mp3，前端只用 `<audio>` 播放，因此**微信 / QQ / 夸克等 App 内置浏览器也能正常听书**（这些浏览器没有 Web Speech API，过去会提示「当前浏览器不支持」）。
- 服务端语音来自百度翻译的在线合成接口，服务器端内置**内存 + 磁盘缓存**（`data/tts-cache`），重复段落不再请求；同一时刻串行请求，做一个有礼貌的客户端。
- **内置 6 种音色**（无需密钥）：`标准女声`（百度原声）+ `温柔女声` / `清亮女声` / `低沉男声` / `磁性男声` / `童声`。后 5 种是对原声做 **ffmpeg `rubberband` 变声**（同时调整基频与共振峰，比单纯变调自然），在服务器本机完成、不额外消耗上游配额；结果按「文本 + 音色」缓存到 `data/tts-cache`，第二次播放即秒开。服务器需安装 `ffmpeg`（含 `rubberband` 滤镜，Ubuntu 的 `ffmpeg` 包默认带）；未安装时只提供「标准女声」。
- 也可切回**浏览器内置语音（Web Speech API）**：在听书面板「朗读方式」里选择「浏览器语音」或「自动」。选「自动」时：浏览器支持就用本机音色，不支持则自动改用服务端语音。
- 中文音色的丰富程度取决于你的系统。Windows / macOS / Android 通常自带中文语音；若列表为空，请在系统「语音 / 辅助功能」里安装中文语音包。
- **想要更自然、更多音色？** 可接入 Azure 神经语音（服务端，需密钥）：

  ```bash
  TTS_PROVIDER=azure \
  AZURE_TTS_KEY=你的密钥 \
  AZURE_TTS_REGION=eastasia \
  npm start
  ```

  启用后 `/api/tts/voices` 会返回云希 / 云扬 / 云健 / 晓晓 / 晓伊 / 晓涵等神经音色。
- 也可 `TTS_PROVIDER=browser` 强制只用浏览器语音（关闭服务端合成）。服务端语音需要联网，**断网离线阅读**时请改用浏览器本地音色。

《听书面板》内置：音色（**6 种，含 5 种变声**）、朗读方式、语速（**1~4 倍速**，也可用 1× / 1.5× / 2× / 3× / 4× 快捷按钮一键切换，播放中即时生效，无需等待重新合成）、音调、音量、定时关闭、读完自动进入下一章，以及**「📖 看原文」**（收起面板并跳到当前正在朗读的那一段，章节不同时自动跳章后再定位）；面板顶栏显示**当前章节标题**。朗读时**当前段落高亮并自动滚动居中**。

> 倍速说明：服务端语音固定按基准速度合成并缓存，倍速由手机端播放器实时调节（`<audio>.playbackRate`），因此**切换倍速无需等待重新合成**，且同一段音频在所有倍速间共用缓存。

### 后台听书与迷你播放条

- 开始听书后，**退出阅读页、切换分类 / 首页 / 书架等页面，朗读都会继续**；章节读完后自动续播下一章，**手动翻章（上一章 / 下一章）也会接着念新章节**（可在面板关闭「读完自动进入下一章」）。
- 页面底部会出现**迷你播放条**：`⏯` 播放/暂停、书名与当前章、`🎧` 展开完整听书面板、`✕` **单独停止**听书。
- 在阅读页里，迷你播放条只在**沉浸净读**时出现；点中间调出底部操作面板时会自动让位。
- 支持的浏览器（如 Android Chrome）会把当前章节同步到**锁屏 / 通知栏**，可直接在锁屏上播放、暂停、切上一段/下一段、停止（Media Session）。
- 打开听书面板并点播放后，面板会**自动收起**，避免一直占据屏幕；需要调音色/倍速时再点 `🎧` 打开。

> 提示：后台播放依赖浏览器允许页面持续播放音频。若手机系统把浏览器后台冻结，声音可能停止；把站点「添加到主屏幕」后体验更稳定。

## 📖 阅读设置与翻页方式

在阅读页点中间调出底部操作面板 → **⚙ 设置**，可调整：

- **翻页方式**：`滚动（下拉）`（默认）/ `左右翻页` / `上下翻页`
- 主题、字号、行距、版心、字体、预加载章节数（0 / 3 / 5 / 10）
- 打开章节时是否默认隐藏工具条、是否请求全屏

### 三种翻页方式

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 滚动（下拉） | 原生上下滚动 | 长内容一拉到底，最省事 |
- **左右翻页**：正文按屏幕高度**自动分页**，点屏幕**左侧 / 右侧**或**左右滑动**翻页；一屏一页，阅读更聚焦。
- **上下翻页**：同样自动分页，点**上方 / 下方**或**上下滑动**翻页。
- **跨章衔接**：读到本章最后一页继续翻，会**自动进入下一章**；在第 1 页往回翻则回上一章。底部进度条会结合「章节序号 + 本章页序号」显示整书进度。
- **即时重排**：切换翻页方式、调整字号 / 行距 / 版心、横竖屏旋转、显示 / 隐藏工具条或迷你播放条，都会**即时重新分页**，不会丢内容。

> 从任意位置开始听：点 🎧 会**从当前看到的那一页的第一段**开始朗读；长按 / 双击某一段则从该段开始。听完本章会自动接着听下一章。

> 从任意位置开始听：点 🎧 会**从当前看到的那一页的第一段**开始朗读；长按 / 双击某一段则从该段开始。听完本章会自动接着听下一章。

### 章节目录（不分页）

- 书籍详情页与阅读器「章节目录」都**不再分页**：一次加载并显示全部章节（走 `GET /api/books/:id/chapters?limit=0`）。
- **一行一章**（单列排布，手机上不再一行两章，长目录滚动更清爽）。
- 顶部「**↑ 正序 / ↓ 倒序**」按钮可切换排列（阅读器抽屉与详情页状态同步），选择记在 `localStorage`，下次沿用。
- 超长目录（> 400 章）自动加 `content-visibility: auto`，跳过屏幕外渲染，保证滚动流畅。
- 「筛选章节」输入框可即时按标题过滤。
